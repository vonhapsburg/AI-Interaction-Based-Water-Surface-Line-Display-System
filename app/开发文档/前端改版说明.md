## 二、与原型的关键差异：算法只有一份

原型是在浏览器里**用 JS 重写了整个求解器**（`props / normalDepth / marchReach / locateJump / buildSegments / solve`，约 700 行）。这正是设计文档 §3.4 里「方式乙」的形态，文档自己写了它的后果：

> 计算逻辑需二次实现，存在双份代码不一致的风险。

我保留了「方式甲」：**页面一行水力计算都没有**，全部 JSON 来自 `gvf_core.py`。

具体到数据来源：

| 显示内容 | 来自 |
|---|---|
| 水面线 `x/h/z_w`、`Fr`、`v` | `Result.segments`（内核逐点数组） |
| 型序徽章 | `Result.facts.type_sequence` |
| 关键数值（h₀/hc/ic/最高水位/最大水深/跃位） | `Result.facts.key_numbers` |
| **力学依据逐条文字** | `Result.facts.reasons`（内核生成，不是前端拼的） |
| 横断面 A/B/P/R/v/Fr/Es/ȳ | `/api/section` → `section_at_point()` |
| 预设算例 | 内核 `PRESETS`（7 个） |

好处很直接：报告里可以写「同一份内核，CLI 自检、单元测试、网页调用走同一条计算路径」，而不用解释两份实现为什么一致。

## 三、为接表单，后端补的三处

### 1. 适配层支持「分段模式」

表单可以直接给 `reaches[]`。原来的 adapter 会先要求单段的 `b/n/i/L`，缺了就判「不完整」——即使分段参数已经齐了。

改法：检测到 `reaches` 就进入分段校验路径，逐段检查 `L/b/n/i/m` 并给出「第 2 段 糙率=0.5 超出上限 0.3」这种定位到段的提示。

### 2. 表单提交是「整体替换」而非「增量合并」

第一版接表单时踩了个坑：先算了「渠首给定水深」的算例，再提交一个不含 `upstream` 的单段参数，会话里上一轮的 `upstream=given_h` 残留，结果 M1 变成了 M3→M2。

修法：提交里带 `reaches` 时，先清掉表单持有的键（Q/reaches/downstream/h0/zw/upstream/up_h/mode/...）再覆盖。对话路径仍是增量——两种语义分开。

### 3. 补 `/api/preset` 与 `segments[].v`

- `/api/preset?name=jump` 把内核 `Params` 转成表单参数，前端切换预设即回填表单并计算；
- `pack()` 增加 `v` 数组，CSV 导出与悬停读数才有真实流速。

## 八、第二轮修订（针对现场反馈的四点）

### ① 默认改成两段、坡度不同

首屏算例改为 **缓坡 0.001（0–300 m）→ 陡坡 0.020（300–600 m）**，渠末自由跌水。打开页面即自动计算，得到：

```
M2（0–300 m） → 坡折处临界（x=300 m） → S2（300–600 m）
```

这样一开始就能看到「同一句话里的两个渠段，水面线不一样」——正是这类系统该先展示的东西。`/api/reset` 之后也回到这个算例。

### ② 横断面没体现梯形：真 bug，已修

原画法有两处错（这两处是从原型 HTML 原样搬过来的）：

- **水体画成了矩形**：四个角都用 `±(b/2 + m·h)`，底宽也被撑宽了；
- **渠身多边形退化**：底边几个点的纵坐标都等于画布底部 `H-pad.b`，实际画出来是一条线。

重写后的坐标约定：`Y(0)` 在画布底部、`Y(top)` 在顶部；渠身按「底宽 b + 两侧 1:m 边坡」画梯形，水体下边 `±b/2`、上边 `±(b/2+m·h)`；h₀/h_c 参考线的长度也随高程变化（梯形上口更宽）。

验证（`dom_smoke.js` 新增用例）：b=6 m、m=1.5、h=1.924 m 时，`B = 6 + 2×1.5×1.924 = 11.772 m`，接口与绘图一致，且 `B > b` 证明断面确实是梯形。

### ③ 表单更好用，对话改动有反馈

- **分组**：渠段整块放进浅灰圆角面板，标题带副说明；段号前加颜色点，与纵剖面分段底色一一对应；
- **分段一览**（表单内）：每段一行「第N段 0–300 m · **缓坡** i=0.001 · i_c=0.0034 · i<i_c · M2」，算完立刻知道每段判成了什么；
- **对话同步高亮**：`syncForm()` 会对比更新前后的参数，被对话改动的输入框闪一下黄底（1.4 s 渐隐）——「我刚说的话已经记进表里」这件事变成可见的。
- 顺带修了一个真问题：之前 `applySlotsToForm(); syncForm();` 是先改后拍快照，diff 永远为空，所以高亮从不触发。现在统一为 `syncForm(slots)`，快照→应用→渲染→比对。

### ④ 强调不同渠段的水面线变化

三处同时强化，避免「整条渠只看到一个型号」：

| 位置 | 做法 |
|---|---|
| 纵剖面 | 各段交替浅底纹；顶部标「第N段 · 缓坡/陡坡」；段间画坡折竖虚线 |
| 表单 | 分段一览行（里程区间 + 坡型 + i vs i_c + 曲线型号） |
| 结果卡 | 新增「分段一览」表：段 / 里程 / i / 坡型 / h₀ / h_c / 曲线，坡型按缓/陡着色 |

坡折处的衔接事件（临界、水跃、水跌）仍以符号画在图上，与分段的型序列对齐。
