## 二、三处参数缺口怎么打的

方案 2.1 指出 agent 槽位与内核字段有三个对不上，逐个落实：

### ① `section` 内核不认，只认 `Reach.m`

内核里断面型式由 `m` 决定（`abs(m) < 1e-12` 即矩形），`Section` 是 `Reach` 的派生属性。所以 adapter 里：

- `section == "rectangular"` → `m = 0`，若原句还给了边坡，记 **H1**「已按矩形处理」；
- `section == "trapezoidal"` → `m` 必须 > 0，否则进缺失项；
- 两者都没有 → 默认矩形 `m=0` 并**明确提示**，不因为少一句话就把可算输入判成缺项。

### ② `given_zw` 要的是水位不是水深

内核 `solve()` 里 `h_down = bc.zw - last.z_b_end`。只给水深不给渠底高程时，方案允许「按 0 处理」，但必须让用户知道。adapter 现在会提示：

> 给的是下游水位 1.500 m，但没给渠底高程，已按渠底高程 0 处理（此时下游水深 = 1.500 m）

并把 `zw` 和 `z_b0` 分别映射到 `Boundary.zw` 和 `Reach.z_b_start`。

### ③ 内核只认 `reaches[]`

单段自动组装：`Reach(index=0, name="单段", x_start=0, x_end=L, i, b, m, n, z_b_start)`。
多段留给 `overrides.reaches` 数组（接口已支持，前端表单未做）。

**参数对应表**（前端第一栏）实际每行都标了 `槽位 → 内核字段 → 取值 → 说明`，例如 `m → Reach.m → 0.0 → 矩形取 0`。

## 三、合法性判定：从「分类表」到「能执行的分支」

方案给了 A~I 九类，但没说判定顺序。实现时按「越界 > 越权 > 矛盾 > 缺项 > 正常」排优先级，`verdict` 只取三个值，直接决定服务端行为：

| verdict | 触发 | 服务端行为 |
|---|---|---|
| `reject` | F 主题越界 / G 参数越界 / I 无法解析 | 不进内核，返回原因 + 合法范围 |
| `incomplete` | E 缺项 / H 可追问类矛盾 | 不进内核，返回缺项 + 追问话术 |
| `ok` | A/B/C/D，以及 H1（矩形带边坡，能改） | 进内核计算 |

判定顺序（关键，错了就会误判）：

```
空/超长/无文字  → I
主题越界关键词   → F
adapter 报越界   → G
H1/H3 矛盾       → H
仍有缺失         → E
反问题口吻       → D
边界被显式描述   → C
发生过数字/单位换算 → B
其余             → A
```

### 实测：41 条覆盖 A~I

`tests/step10_legality.py` 一次性跑完，结果 `pass 41 / 41`。其中 10 条 A、12 条 B、1 条 C、5 条 E、5 条 F、4 条 G、2 条 H、2 条 I，同时把每条能算的输入直接喂进内核核对曲线型。

## 五、调试中发现的真实问题（9 个）

### 1. `长1000米` 解析不出渠长【方案 A4/A8 必踩】

原规则只认 `渠长|长度|算|计算`，而 `长1000米` 的「长」不在其中，第二条例句又要求「长」在数字之后。A4、A8 都会因此缺 L。

修复：补 `(?:全长|总长|长)\s*NUM` 与 `L=…` 两条正则。

### 2. 没写断面型式的句子被判成「缺断面」

`平坡渠，底宽5米…`（A10）、`五米宽的渠…`（B1）都没有「矩形/梯形」字样，直接进缺失项，明明内核只需要 `b` 和 `m`。修复：section 缺失且 m 也缺失时默认矩形（m=0）并提示。

### 3. 模型把没提断面的句子判成梯形，凭空要边坡

B1 走模型通道时，qwen 返回 `"section":"trapezoidal"`（原句根本没提断面），adapter 于是要求 m，把可算输入变成不完整。

修复两手：提示词加「只有出现梯形/边坡才填 trapezoidal」；adapter 加确定性护栏——**原句无「梯形/边坡」字样时不采信模型的 trapezoidal**。

### 4. 合法性判为「不完整」时服务端仍去算

H3（平坡 + 正常水深）判定是 `incomplete`，但 adapter 仍然拼出了 Params，服务端只检查了 `verdict == "reject"` 就放行，结果内核算出空曲线。修复：`incomplete` 一律不进内核。

### 5. `h0` 被当成 C 类边界

最初把「给了水深」也算边界推定，导致几乎所有 A 类都被判成 C。修复：只有「下游/渠末水深、水位、正常水深、渠首水深」才算 C，普通「水深 2 米」是 A 的常态。

### 6. 「百分之零点一」处理顺序错

`零点一` 是小数口语，`百分之` 的正则字符集里没有「点」，原来先做「分之」再做「零点」，于是「百分之零点一」匹配失败。修复：先转「零点一 → 0.1」，再做分之换算。

### 7. `万分之五` 不支持

`normalize()` 的分母表只有 千/百/十。修复：加入「万」（万分之五 → 0.0005）。

### 8. `一米二` 被读成 1.0

「一米二」是口语里的 1.2，原逻辑会把「一米」转成 1、留下孤立的「二」。修复：在单位归一化之前先匹配 `X米Y` → `X.Y`。

### 9. 符号写法 `b=5` `L=600m` 不支持

方案 A2/A6/A8 都用这种写法，原规则只有 `Q=`、`n=`、`i=`。修复：补 `b=`、`L=`，并把「为/是/取」加进各字段的连接词。

顺带：参数对应表里 `zw` 行原来对所有非水位边界都显示红色「缺失」，容易误导，已改成只在水位边界时出现。

## 六、与方案的偏差（3 处，都有依据）

### ① A1 被判为 B 类，不是 A

A1「…底坡**千分之一**…」本身就需要换算。方案把 A1 归 A，但把同样含「千分之一」的 B1 归 B、把「万分之五」的 B7 归 B，口径不自洽。

我选了自洽规则：**分数词（千分之一/万分之五/百分之五）一律算 B**。这样 A 类就是纯「阿拉伯数字 + 标准单位」，含义清晰。A1 的计算结果不受影响（仍是 M1）。

### ② A9 出 S3，不是 S2

方案验收第 3 条写「出 S2」。但 A9 参数是 i=0.02、b=5、n=0.015、Q=10、渠首 h=0.3 m：

- 临界水深 hc = (Q²/(g·b²))^(1/3) ≈ **0.741 m**
- 给定 h=0.3 m < hc → 处于第 3 区 → 物理上只能是 **S3**

内核给 S3 是对的，方案写 S2 应是笔误。报告里保留这个差异，不为了对齐文字去改内核。

### ③ 参数对应表是 10 行，不是 12 行

方案说「12 行全有值」。实际输出按本次计算**真正相关**的字段生成：`section, b, m, n, i, Q, h0, L, z_b0, downstream` 共 10 行；`zw` 只在水位边界时出现。硬凑 12 行会把不适用的字段也标成「缺失」，反而误导。

## 八、残留风险

1. **模型幻觉仍未根除**。断面型式已有护栏，但其它字段若模型编造且规则恰好没给，仍可能进入计算。建议在 adapter 出口加一道「量纲/物理合理性」校验（例如 `h0` 与 `hc` 的关系、`Fr` 是否合理）。
2. **多段变坡只能走接口**（`overrides.reaches`），前端表单没做。方案 I4 提到「8 段变坡口头描述」——目前会提示改用表单。
3. **反问题（D 类）只提示不计算**。内核已有 `solve_inverse`，还没接进 `/api/solve`。
4. **`_selftest` 未纳入 CI**。内核自带自检，可以顺手在启动时跑一次，作为「内核可用」的证据。
5. **无头截图受限**。若需要视觉回归，得在沙箱外跑浏览器或放宽权限。
